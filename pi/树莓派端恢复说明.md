# 树莓派端：优先保留现有环境

本文件供 Agent 或有经验者处理树莓派。原设备在 2026-11-17 检查时：Ubuntu 24.04.4 arm64；Docker `humble` 容器使用 ROS 2 Humble 和 host 网络；原工作区仍保留；`spore-vehicle-stack` 提供底盘驱动，`spore-rosbridge` 提供 9091。默认配置 `/dev/ttyACM0`、115200、ROS_DOMAIN_ID=77。树莓派自身没有格式化，所以正常情况下无需重装或替换。

`driver/spore_patrol_base_driver/` 包含原底盘驱动源码、配置和协议实现；控制台依赖该驱动发布名称为 `spore_patrol_base_driver/STM32` 的 `/diagnostics`，以及 `/cmd_vel` 的 `geometry_msgs/msg/Twist`。源码内保留原 ROS 包名以兼容。2026-11-17 已对照主驱动、协议与配置三项 SHA-256 和原树莓派匹配，未声称所有目录或运行中的二进制完全一致。

## 恢复路线

1. **优先修复既有环境。** 检查服务日志、容器、工作区、网络和 USB。不要重新刷机、覆盖工作区或更改固件。旧栈包含雷达、定位等额外组件，可能在未连接传感器时产生错误；底盘功能是否可用仍以其诊断为准。
2. 若旧环境确实不可用，本包提供独立恢复镜像作为备选：先确认已安装并运行 Docker Engine、镜像源/apt 网络可访问；缺 Docker 时由 Agent 按该机系统和官方说明安装，成员通过本机 sudo 提示授权。构建只使用本包驱动，依赖从网络下载：在树莓派上进入 `pi/`，运行 `./build-recovery.sh`。构建不会启动车辆驱动。
3. 确认 USB 对应的底盘串口和权限；当前恢复脚本要求设备实际存在。现有 `spore-vehicle-stack` 或 `spore-rosbridge` 服务运行中、9091 被占用时脚本拒绝启动。必须先诊断现有服务并与现场成员协调，确保没有其他程序占用底盘或发布运动命令。不得直接将两个底盘驱动并行运行。
4. 在设备可用且现场有人照看时运行 `./run-recovery.sh /dev/ttyACM0`（按实际设备调整）。脚本使用 host 网络及 `--device` 直通该串口，前台启动独立容器，容器同时运行底盘节点和 rosbridge；关闭终端或 Ctrl+C 会停止该容器。它不配置开机自启，也不会主动发送非零速度。请检查两个进程和诊断是否正常；容器启动并不代表底盘就绪。
5. 电脑端重连控制台并做只读状态检查，再由现场成员决定何时架空轮开展实车测试。

**未验证项：**独立恢复镜像和脚本未在真实树莓派上构建或接车测试；它们是可执行的恢复方案，不是已经验证的替代生产环境。底盘更换、固件变化、串口变化、镜像或软件源不可达都可能需要调整。rosbridge 在 0.0.0.0:9091 提供无认证访问，必须限定可信的隔离网络，不能暴露公网。实际物理急停及断链停车需单独实测。
